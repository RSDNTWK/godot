# FFmpeg source patches

Apply these patches to the pinned FFmpeg 9.0.2 source before building SDKs.
The HLS patches retain the engine's validated custom HTTPS IO and timestamp
checks.

`arm32-ndk-neon-syntax.patch` removes GNU-only `.dn` typed-register aliases
from the two ARM32 RGB-to-NV12 kernels. Register lanes are explicit and the
multiply instructions carry their existing `.s16` type. The dispatch and
assembly guards use `HAVE_NEON`, since `.dn` support is no longer needed.
This allows the Android NDK's integrated assembler to build those kernels
without an external GNU assembler. ARM64 is unaffected.

`../tests/check_arm32_neon_syntax.py` accepts `--source`, `--config`, `--cc`
and `--objcopy`. Use an ARM/NEON FFmpeg configuration generated by the NDK
with `HAVE_AS_DN_DIRECTIVE=0`. It checks both kernels' machine instructions
against the byte-identical original GNU-assembled code. The syntax rewrite
also passed 36 direct routine comparisons on the Nokia XR20, including
16/32-bit arithmetic, padded strides, signed coefficients and 1080p inputs.
Those comparisons use widths divisible by 16 and even heights. This describes
the syntax patch alone, before applying the safety patch below.

Apply `arm32-unscaled-conversion-safety.patch` after the syntax patch. It fixes
the reproduced width-17 SIGBUS by selecting the general converter for widths
not divisible by 16 and odd heights. The retained optimized kernel uses byte
stores that tolerate unaligned destination addresses/strides. Incomplete row
pairs are rejected before touching buffers. The RGB wrappers now use the
already-offset source slice supplied by FFmpeg, and all four ARM unscaled
wrappers return the number of rows produced rather than zero.

Use `--safety-patch` with the syntax check when both patches are applied. Its
pinned instruction hashes include the reviewed store fix: four `vstmia`
instructions in each kernel become `vst1.8`; arithmetic stays unchanged.
Both patched kernels compile with Android NDK 29 and 30.

`../tests/arm32_unscaled_regression.c` builds against the patched SDK and runs
on an ARM32-capable Android device. The Nokia XR20 passed 112 full-frame cases,
48 forward/reverse slice cases, 40 rejected incomplete row-pair cases, ten
two-thread frame conversions, and eight NV12/NV21/YUV420P/YUV422P row-count
cases. These initial comparisons used aligned fallback buffers.

`arm32-rgb-unaligned-input.patch` fixes the additional generic RGB fault found
at 2x3 with a byte-offset buffer. It replaces an aligned-only packed RGB load
with the matching unaligned-safe load; the arithmetic is unchanged. The
expanded Nokia regression passes all 112 full-frame cases with byte-unaligned
input/output addresses and strides on both optimized and fallback paths,
including negative strides, as well as the slice/guard/threaded checks above.
It now checks 16 YUV row-count cases, covering bilinear and point filtering.

`arm32-unscaled-filter-selection.patch` restricts the nearest-neighbour
unscaled YUV-to-RGB shortcut to explicit `SWS_POINT` requests without
`SWS_BITEXACT`. Bilinear and other filters retain their general filtering path.
This restores all 8,294,400 tested RGBA components to byte-identical output for
1080p NV12 input, including chroma edges that previously differed by 115.

These source fixes have been tested in an isolated, fully rebuilt NDK SDK.
The distributed ARM32 SDK remains unchanged. With two conversion workers, the
assembly-enabled candidate measured about 16.6 ms for the 1080p NV12 case,
compared with about 11.7 ms using the existing SDK. The release therefore keeps
the faster existing SDK and the bounded two-worker engine change. These source
patches remain available for subsequent SDK rebuilds; passing these component
regressions does not qualify an entire engine/player release.
